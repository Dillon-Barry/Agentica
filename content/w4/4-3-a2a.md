MCP connects an agent to *tools*. But what about agents built by different teams, or different companies, working together? That's **A2A**, the Agent2Agent protocol.
===
Google introduced A2A in April 2025 and gave it to the Linux Foundation that June. It's an open standard, now at version 1.0.
===
Each agent publishes an **Agent Card**: a small JSON file at a known web address, listing its name, skills, endpoint and how to authenticate.
===
A client agent reads the card, sends a **task**, and gets progress updates and results back. The other agent keeps its own tools and data private.
===
Easy rule: **MCP** = agent to tool. **A2A** = agent to agent. Real systems use both.
=== deeper
A2A runs over HTTPS using JSON-RPC, streams progress for long tasks, and lets agents swap text, files and structured data. Because agents can now call agents across team and company lines, A2A raises the same questions as any API: who is calling, are they allowed, and what did they do? Those questions come back in World 6.
=== peek
An Agent Card (trimmed), published at /.well-known/agent-card.json. Other agents read it to learn what this agent can do and how to reach it.

```json
{
  "name": "Route Planner Agent",
  "description": "Plans routes and travel times.",
  "version": "1.2.0",
  "supportedInterfaces": [
    { "url": "https://routes.example.com/a2a/v1", "protocolBinding": "JSONRPC" }
  ],
  "capabilities": { "streaming": true },
  "skills": [
    { "id": "route-optimizer", "name": "Route optimizer",
      "description": "Finds the fastest route between places." }
  ]
}
```
